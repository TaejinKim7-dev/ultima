# AI 코딩 에이전트 인계 규칙

이 문서는 이 프로젝트를 다른 AI 코딩 에이전트가 자연스럽게 이어받기 위한 공통 인계 규칙이다. `handoff.md`는 항상 이 문서의 포맷을 따라 최신 상태를 기록한다.

## 핵심 원칙

`handoff.md`는 대화 요약이 아니라 재현 가능한 작업 지시서여야 한다.

다음 에이전트는 이전 대화를 보지 않아도 `README.md`, `AGENTS.md`, `handoff.md`, `docs/ULTIMA_WEB_PLAN.md`, `docs/TESTING_POLICY.md`만 읽고 바로 작업을 시작할 수 있어야 한다.

## 필수 포함 항목

### 1. 현재 목표

현재 작업이 무엇을 완성하려는지 한 문단으로 쓴다.

예:

- Todo 1: 빌드/테스트 기반 구성
- GitHub Pages에서 실행 가능한 웹 포팅 기반 준비
- 원본 게임 데이터 미포함 정책 유지

### 2. 확정된 방향

이미 결정된 기술·제품·운영 방식을 적는다.

- GitHub Pages 정적 배포
- `HTML + TypeScript + WebAssembly + WebGL2 + Web Audio`
- feature branch + PR 흐름
- TDD 및 컴포넌트별 Unit Test
- 한국어 번역은 repo 내부 원천 파일로 관리
- 원본 게임 데이터는 사용자가 브라우저에서 직접 선택

### 3. 현재 작업 상태

다음 에이전트가 상태를 재현할 수 있게 구체적으로 적는다.

- 현재 브랜치
- 마지막 관련 커밋
- 수정한 파일
- 생성한 문서
- 실행한 명령
- 통과한 테스트
- 실패한 테스트와 실패 이유
- 아직 커밋하지 않은 변경

### 4. 다음 에이전트가 바로 할 일

작업명만 쓰지 말고, 바로 실행 가능한 단위로 쓴다.

좋은 예:

1. `todo-01-build-test-harness` 브랜치에서 `npm ci`가 통과하는지 확인한다.
2. `npm run test:unit`으로 repo source 검증 테스트를 실행한다.
3. `npm run verify:repo-sources`가 원본 게임 데이터 포함 여부를 차단하는지 확인한다.
4. Todo 2 착수 전 `docs/NEXT_THREE_STEPS.md`의 선행 조건을 확인한다.

나쁜 예:

- 빌드 시스템 만들기
- 테스트 추가하기
- 다음 단계 진행하기

### 5. 금지사항

반드시 지켜야 할 안전 경계를 반복해서 적는다.

- 원본 Ultima IV 데이터 커밋 금지
- private corpus 커밋 금지
- 사용자 save 커밋 금지
- secret, token, env dump 커밋 금지
- 실패 테스트 삭제 금지
- 검증하지 않은 명령을 통과한 것처럼 기록 금지

### 6. 검증 명령

작업자가 실제로 실행해야 하는 명령을 적는다. 명령이 아직 존재하지 않으면 “예정”이라고 표시한다.

예:

```bash
npm ci
npm run test:unit
npm run verify:repo-sources
npm run typecheck
npm run build
```

### 7. 남은 위험과 미검증 사실

아직 사실로 확정하지 않은 내용을 분리해서 적는다.

- 실행하지 않은 빌드
- 실제 브라우저에서 확인하지 않은 기능
- native 기준선 미확보
- wasm 빌드 미검증
- GitHub Pages 배포 미검증

## 갱신 시점

`handoff.md`는 다음 시점마다 갱신한다.

- Todo를 시작할 때
- Todo를 완료했을 때
- branch/commit/PR 상태가 바뀌었을 때
- 테스트 결과가 바뀌었을 때
- blocker가 생겼을 때
- 다른 AI 에이전트에게 작업을 넘기기 전

## 완료 기준

인계가 완료되었다고 보려면 다음 질문에 모두 답할 수 있어야 한다.

- 다음 에이전트가 현재 목표를 한 문장으로 말할 수 있는가?
- 다음 에이전트가 어떤 파일을 읽어야 하는지 아는가?
- 다음 에이전트가 첫 번째로 실행할 명령을 아는가?
- 원본 데이터와 secret을 커밋하면 안 된다는 점이 명확한가?
- 어떤 테스트가 통과했고 어떤 검증이 아직 남았는지 분리되어 있는가?
